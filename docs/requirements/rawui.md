# RawUI 需求

## 定位

RawUI 是 xserial 的默认交互界面，面向输出文本内容或提供 Shell/Console 的串口设备。

它的首要价值是像传统串口终端一样直接：用户键盘输入进入设备，设备字节原样出现在当前终端。RawUI 不解析设备日志格式，不重绘设备内容，也不把本地提示混入设备输出。

RawUI 通过 [Middleware](middleware.md) 使用 [Backend](backend.md)，不直接拥有串口或实现文件传输协议。

## 启动与兼容

- 不带 `--TUI` 时默认进入 RawUI。
- 使用以下唯一连接形式：

  ```text
  xserial <port> [cfg]
  ```

- 完全没有位置参数时显示帮助；使用 `list` 子命令列出可用串口，其他位置参数直接视为端口名。
- `help`、`list`、`version` 和 `completion` 是工具命令；不提供 `conn` 子命令。
- cfg 按 `baud,data-bits,parity,stop-bits` 排列并允许从右侧省略，默认补全为 `115200,8,N,1`；不提供 `-c|--cfg`。
- 保留现有 prefix key 和本地命令，不要求用户重新学习基本操作。

## 文本与 Shell 交互

- 进入会话前保存当前终端状态并切换到 raw mode。
- 普通键盘字节直接发送给设备，不增加编码、换行或命令解释。
- 默认情况下设备接收字节原样写入 stdout，不转换换行、不剥离 ANSI。
- 启用 `--time` 后，RawUI 在每个接收行开头实时插入时间前缀；不启用时不得插入。
- `-t` / `--time` 是布尔开关，时间格式固定为 `15:04:05.000`，不支持自定义格式。
- RawUI 自身的帮助、状态、进度和错误只写 stderr。
- raw mode 下的本地输出使用 CRLF，确保提示从行首开始且不会破坏光标位置。
- 发送未完成、设备断开或 Middleware 正被独占时，必须给出本地提示，不能把失败输入延迟到之后发送。

## Prefix 命令

默认 prefix 为 `Ctrl-P`。按下 prefix 后，下一个按键属于本地命令：

| 按键 | 行为 |
|---|---|
| `Ctrl-P h` | 显示本地帮助 |
| `Ctrl-P Ctrl-U` | YMODEM 上传 |
| `Ctrl-P Ctrl-D` | YMODEM 下载 |
| `Ctrl-P q` | 退出会话 |
| `Ctrl-P Ctrl-P` | 向设备发送字节 `0x10` |

- 未注册的 prefix 组合不应静默执行意外动作；应给出简洁提示并恢复普通输入状态。
- 帮助内容由同一命令定义生成，按键识别与帮助文本不能分别维护。
- 架构上保留替换 prefix key 的能力，本轮不增加用户配置入口。

## 文件传输交互

### 路径输入

- 启动上传后，在 stderr 提示输入本地文件路径。
- 用户可以正常编辑路径；空路径或 Esc 取消并返回终端透传。
- 路径无效、文件不存在或不是普通文件时，显示错误并保持会话可用。
- 路径输入期间普通字符不得发送给设备。

### YMODEM

- 上传先输入本地文件路径；下载保存到当前目录。
- 下载不得覆盖已存在文件。
- 传输期间 Middleware 独占双向串口，YMODEM 协议字节不得出现在 stdout。
- stderr 显示方向、进度、重试和最终统计。
- Esc 取消并恢复普通终端流。
- 断线时传输失败，不自动续传；Backend 可以继续执行有限次重连。

## 断线与退出

- 设备断开后，在 stderr 显示断线原因和当前重连次数。
- 重连期间 stdin 仍响应 prefix quit，但普通输入不缓存、不在重连后补发。
- 重连成功后显示一次成功状态并继续当前 RawUI。
- 重连耗尽后显示最终错误、恢复终端并退出。
- 用户退出、父 context 取消、stdin EOF、前端错误和 Backend 错误都必须恢复终端。
- 终端恢复失败需要返回给命令层，不能被原始错误覆盖或静默忽略。

## 输出边界

```text
stdout: 设备原始字节
stderr: RawUI 提示、帮助、进度、状态和错误
```

- 结构化业务日志不得插入 stdout。
- 传输协议字节在独占期间不得作为设备文本输出。
- 本地进度结束后，下一段设备输出必须从正确的终端位置继续，不能粘连在进度行中。

## 可用性与质量

- RawUI 在常规终端尺寸下不依赖全屏绘制。
- Prefix 状态机、路径输入、传输取消、断线退出和 terminal restore 必须可用内存 fake 测试。
- stdin 阻塞读取必须可被会话取消解除，RawUI 退出后不能遗留读取 goroutine。
- 测试应同时验证默认 stdout 的逐字节透明性、`--time` 跨数据块的逐行前缀，以及 stderr 的 CRLF 契约。

## 本轮不包含

- Text 日志高亮、搜索或过滤；
- Hex 输入和 hexdump；
- 全屏布局；
- 协议字段解析；
- `--log` 和记录格式的重新设计。现有行为保持兼容，后续单独制定需求。
